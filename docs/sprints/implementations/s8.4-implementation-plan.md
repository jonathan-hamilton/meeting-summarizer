# S8.4 Mobile File Upload Flow Redesign - Implementation Plan

## Story Overview
**S8.4: Redesign File Upload Flow for Mobile**  
As a mobile user, I want to easily upload audio files from my device so that I can use the transcription service on mobile devices.

## Acceptance Criteria
1. File upload interface works seamlessly with mobile file pickers
2. Drag-and-drop zones are touch-friendly and appropriately sized
3. Upload progress indicators are clearly visible on mobile screens
4. Desktop drag-and-drop functionality remains fully intact

## Dependencies
- ✅ S8.1 - Responsive Breakpoint System (COMPLETE)
- ✅ S8.3 - Touch Optimization (COMPLETE)

## Technical Approach

### Current State Analysis
- **FileUpload.tsx**: Main orchestration component with upload queue management
- **FileDropzone.tsx**: Drag/drop interface with basic mobile detection
- **react-dropzone**: Handles file picker and drag/drop functionality
- **Existing Issues**: Some application state using React `useState` instead of Zustand stores

### Architecture Compliance

#### 🏗️ MANDATORY: Design Pattern Validation
- ✅ **Factory Pattern**: Currently compliant - uses `createApiService(mode)`
- ⚠️ **State Management**: Needs refactoring - several `useState` for application state
- ✅ **Provider Pattern**: Uses React Context appropriately
- ✅ **Existing Responsive Foundation**: S8.1 breakpoints, S8.3 touch optimization

#### Pattern Compliance Issues to Address:
- `tokenDialogOpen`, `costDialogOpen` - Move to dialog store
- `pendingFile`, `pendingTokenCalc` - Move to upload store  
- `validationErrors`, `tokenError` - Move to upload store

## Implementation Increments

### Increment 1: State Management Refactoring
**Purpose**: Achieve design pattern compliance by moving application state to Zustand stores  
**Acceptance Criteria Addressed**: Foundation for mobile optimization  
**Design Patterns Applied**: 
- Zustand State Management pattern (MANDATORY compliance)
- Maintains Factory pattern for API services

**Technical Changes**:
- Create/extend `useFileUploadStore` for upload-specific state
- Create/extend `useDialogStore` for dialog management
- Remove `useState` for application state, keep only for ephemeral UI
- Maintain all existing functionality

**Working State**: No functional changes, just architectural compliance
