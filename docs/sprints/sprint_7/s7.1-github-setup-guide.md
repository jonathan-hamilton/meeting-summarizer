# S7.1 GitHub Setup Guide

## Overview

This guide provides step-by-step instructions for setting up GitHub environments, secrets, and permissions required for the CI/CD pipeline.

## **🔧 GitHub Environment Setup**

### Step 1: Create GitHub Environments

1. **Navigate to Repository Settings**
   - Go to your GitHub repository
   - Click "Settings" tab
   - Select "Environments" from the left sidebar

2. **Create Development Environment**
   - Click "New environment"
   - Name: `development`
   - Protection rules: None (allow immediate deployment)
   - Click "Configure environment"

3. **Create Production Environment**
   - Click "New environment"
   - Name: `production`
   - Protection rules:
     - ✅ Required reviewers: 2
     - ✅ Restrict deployments to specific branches: `main`
     - ✅ Prevent self-review
   - Add reviewers from production deployment team
   - Click "Configure environment"

4. **Create Production Approval Environment**
   - Click "New environment"
   - Name: `production-approval`
   - Protection rules:
     - ✅ Required reviewers: 1
     - ✅ Restrict deployments to specific branches: `main`
     - ✅ Prevent self-review
   - Add reviewers from release management team
   - Click "Configure environment"

### Step 2: Configure Azure Service Principals

#### Create Development Service Principal
```bash
# Login to Azure CLI
az login

# Create service principal for development
az ad sp create-for-rbac \
  --name "meetingsummary-dev-github" \
  --role "Contributor" \
  --scopes "/subscriptions/YOUR_SUBSCRIPTION_ID/resourceGroups/rg-meetingsummary-dev" \
  --json-auth

# Save the output - you'll need the clientId for GitHub secrets
```

#### Create Production Service Principal
```bash
# Create service principal for production
az ad sp create-for-rbac \
  --name "meetingsummary-prod-github" \
  --role "Contributor" \
  --scopes "/subscriptions/YOUR_SUBSCRIPTION_ID/resourceGroups/rg-meetingsummary-prod" \
  --json-auth

# Save the output - you'll need the clientId for GitHub secrets
```

### Step 3: Configure GitHub OIDC

#### Enable OIDC for Development
```bash
# Add federated credential for development environment
az ad app federated-credential create \
  --id CLIENT_ID_FROM_DEV_SP \
  --parameters '{
    "name": "meetingsummary-dev-github-oidc",
    "issuer": "https://token.actions.githubusercontent.com",
    "subject": "repo:jonathan-hamilton/meeting-summarizer:environment:development",
    "description": "GitHub Actions OIDC for development environment",
    "audiences": ["api://AzureADTokenExchange"]
  }'
```

#### Enable OIDC for Production
```bash
# Add federated credential for production environment
az ad app federated-credential create \
  --id CLIENT_ID_FROM_PROD_SP \
  --parameters '{
    "name": "meetingsummary-prod-github-oidc",
    "issuer": "https://token.actions.githubusercontent.com",
    "subject": "repo:jonathan-hamilton/meeting-summarizer:environment:production",
    "description": "GitHub Actions OIDC for production environment",
    "audiences": ["api://AzureADTokenExchange"]
  }'

# Add federated credential for production approval
az ad app federated-credential create \
  --id CLIENT_ID_FROM_PROD_SP \
  --parameters '{
    "name": "meetingsummary-prod-approval-github-oidc",
    "issuer": "https://token.actions.githubusercontent.com",
    "subject": "repo:jonathan-hamilton/meeting-summarizer:environment:production-approval",
    "description": "GitHub Actions OIDC for production approval environment",
    "audiences": ["api://AzureADTokenExchange"]
  }'
```

## **🔐 GitHub Secrets Configuration**

### Repository Variables (Settings > Secrets and variables > Actions > Variables)

Add these variables at the repository level:

```yaml
AZURE_SUBSCRIPTION_ID: "your-azure-subscription-id"
AZURE_TENANT_ID: "your-azure-tenant-id"
AZURE_LOCATION: "East US"
TERRAFORM_STORAGE_ACCOUNT: "your-terraform-storage-account"
TERRAFORM_CONTAINER: "terraform-state"
TERRAFORM_RESOURCE_GROUP: "rg-terraform-state"
```

### Development Environment Secrets

Navigate to: Settings > Environments > development > Add secret

```yaml
AZURE_CLIENT_ID: "development-service-principal-client-id"
```

## **🏗️ Terraform Backend Setup**

### Create Terraform State Storage

```bash
# Create resource group for Terraform state
az group create \
  --name rg-terraform-state \
  --location "East US"

# Create storage account for Terraform state
az storage account create \
  --name "your-terraform-storage-account" \
  --resource-group rg-terraform-state \
  --location "East US" \
  --sku Standard_LRS \
  --encryption-services blob

# Create container for Terraform state
az storage container create \
  --name terraform-state \
  --account-name "your-terraform-storage-account"
```

### Grant Service Principal Access

```bash
# Grant development service principal access to Terraform state
az role assignment create \
  --assignee CLIENT_ID_FROM_DEV_SP \
  --role "Storage Blob Data Contributor" \
  --scope "/subscriptions/YOUR_SUBSCRIPTION_ID/resourceGroups/rg-terraform-state/providers/Microsoft.Storage/storageAccounts/your-terraform-storage-account"

# Grant production service principal access to Terraform state
az role assignment create \
  --assignee CLIENT_ID_FROM_PROD_SP \
  --role "Storage Blob Data Contributor" \
  --scope "/subscriptions/YOUR_SUBSCRIPTION_ID/resourceGroups/rg-terraform-state/providers/Microsoft.Storage/storageAccounts/your-terraform-storage-account"
```

## **👥 Team Permissions Setup**

### Create GitHub Teams

1. **Navigate to Organization Settings**
   - Go to your GitHub organization
   - Click "Settings"
   - Select "Teams"

2. **Create Required Teams**

#### Production Deployment Team
- **Name**: `production-deployment-team`
- **Description**: "Team authorized to approve production deployments"
- **Members**: Senior engineers, DevOps engineers, Engineering managers
- **Permissions**: Write access to repository

#### Release Management Team
- **Name**: `release-management-team`
- **Description**: "Team responsible for release planning and approval gates"
- **Members**: Product managers, Release managers, Engineering leads
- **Permissions**: Read access to repository (enough for approval)

#### Senior Engineers Team
- **Name**: `senior-engineers`
- **Description**: "Senior engineering team members"
- **Members**: Senior software engineers, Principal engineers
- **Permissions**: Write access to repository

### Configure Branch Protection

Navigate to: Settings > Branches > Add rule

**Rule for `main` branch**:
- ✅ Require a pull request before merging
- ✅ Require approvals: 2
- ✅ Dismiss stale PR approvals when new commits are pushed
- ✅ Require review from code owners
- ✅ Require status checks to pass before merging
- ✅ Require branches to be up to date before merging
- ✅ Require signed commits
- ✅ Include administrators

**Required status checks**:
- `Build & Test / build-backend`
- `Build & Test / build-frontend`
- `Build & Test / integration-tests`

## **📞 Support**

If you encounter issues during setup:

1. **Check GitHub Actions logs** for detailed error messages
2. **Verify Azure CLI permissions** for service principal operations
3. **Confirm subscription quotas** for Azure resources
4. **Review environment configurations** for typos or missing values

### Common Issues

#### Issue: OIDC Authentication Failures
**Solution**: Verify federated credentials are configured correctly with the exact repository and environment names.

#### Issue: Terraform Backend Access Denied
**Solution**: Ensure service principals have "Storage Blob Data Contributor" role on the Terraform state storage account.

#### Issue: Environment Approval Not Working
**Solution**: Verify reviewers are added to the environment and have correct permissions on the repository.
