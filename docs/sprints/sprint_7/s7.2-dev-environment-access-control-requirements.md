## Requirements

### Functional Requirements

#### FR-1: Invitation-Based Registration Protection
- **FR-1.1**: Development environment MUST require valid invitation codes for user registration
- **FR-1.2**: Production environment MUST NOT require invitation codes (zero impact on production flow)
- **FR-1.3**: Invalid or missing invitation codes MUST return user-friendly error messages
- **FR-1.4**: Invitation codes MUST be single-use and expire after a configurable time period

#### FR-2: Invitation Code Management
- **FR-2.1**: System MUST generate unique, secure invitation codes
- **FR-2.2**: Invitation codes MAY be restricted to specific email addresses (optional)
- **FR-2.3**: Administrators MUST be able to generate invitation codes via API endpoints
- **FR-2.4**: System MUST track invitation code usage and lifecycle

#### FR-3: User Experience
- **FR-3.1**: Invitation URLs MUST auto-populate invitation codes in registration form
- **FR-3.2**: Error messages MUST clearly explain invitation requirement and provide admin contact guidance
- **FR-3.3**: Registration form MUST conditionally display invitation code field only in development environment

#### FR-4: Administrative Features
- **FR-4.1**: Admin endpoints MUST allow generating invitation codes with optional email restriction
- **FR-4.2**: Admin endpoints MUST provide invitation code status and usage tracking
- **FR-4.3**: System MUST log all invitation-related activities for audit purposes

### Non-Functional Requirements

#### NFR-1: Security
- **NFR-1.1**: Invitation codes MUST be cryptographically secure and unpredictable
- **NFR-1.2**: System MUST prevent invitation code enumeration attacks
- **NFR-1.3**: Expired or used invitation codes MUST be invalid for future use

#### NFR-2: Performance
- **NFR-2.1**: Invitation code validation MUST NOT add >100ms to registration request processing
- **NFR-2.2**: Database queries for invitation validation MUST be optimized with appropriate indexes

#### NFR-3: Maintainability
- **NFR-3.1**: Invitation system MUST be entirely optional and configurable via environment settings
- **NFR-3.2**: Code MUST maintain clear separation between dev and production logic paths

## Technical Architecture

### Database Schema

```sql
CREATE TABLE InvitationCodes (
    Id UNIQUEIDENTIFIER PRIMARY KEY DEFAULT NEWID(),
    Code NVARCHAR(50) NOT NULL UNIQUE,
    Email NVARCHAR(255) NULL,              -- Optional email restriction
    ExpiresAt DATETIME2 NOT NULL,
    UsedAt DATETIME2 NULL,
    UsedByUserId UNIQUEIDENTIFIER NULL,
    IsActive BIT NOT NULL DEFAULT 1,
    CreatedAt DATETIME2 NOT NULL DEFAULT GETUTCDATE(),
    CreatedBy NVARCHAR(255) NOT NULL,
    
    -- Indexes for performance
    INDEX IX_InvitationCodes_Code (Code),
    INDEX IX_InvitationCodes_Email (Email),
    INDEX IX_InvitationCodes_ExpiresAt (ExpiresAt),
    INDEX IX_InvitationCodes_IsActive (IsActive)
);
```

[HttpPost("register")]
public async Task<ActionResult<AuthResponse>> Register([FromBody] RegisterRequest request)
{
    try
    {
        // DEV ENVIRONMENT PROTECTION
        if (_hostEnvironment.IsDevelopment() && _environmentOptions.RequireInvitation)
        {
            if (string.IsNullOrWhiteSpace(request.InvitationCode))
            {
                return BadRequest(new { 
                    message = "Invitation code required for development environment access. Please contact an administrator for access." 
                });
            }

            var isValidInvite = await _invitationService.ValidateInvitationCodeAsync(request.InvitationCode, request.Email);
            if (!isValidInvite)
            {
                return BadRequest(new { 
                    message = "Invalid or expired invitation code. Please contact an administrator for a new invitation." 
                });
            }
        }

        // ... existing registration logic ...

        }

        return CreatedAtAction(nameof(GetProfile), new { }, response);
