## Technical Notes

### **Architecture Decision**
- **From**: Complex real-time SignalR infrastructure with WebSocket connections, hub management, and state synchronization
- **To**: Simple React/MUI progress indicators with file-size-based estimation and polling for completion status
- **Benefits**: Reduced complexity, easier maintenance, fewer potential failure points, simplified debugging

### **Infinite Loop Resolution**
The removal process uncovered and fixed critical infinite render loops in the FileUpload component:
- **Root Cause**: Non-memoized callback functions were causing useEffect to trigger infinitely
- **Solution**: Added proper `useCallback` memoization to `handleTranscriptionCompleteWrapper` and related functions
- **Prevention**: Added `useRef` tracking to prevent duplicate completion callback executions

### **Migration Strategy**
- **Phase 1**: Backend SignalR removal (hub, controller cleanup, service registrations)
- **Phase 2**: Frontend SignalR removal (services, hooks, components, dependencies)
- **Phase 3**: React/MUI progress implementation (planned for next iteration)

### **Future Implementation (Phase 3)**
Next phase will implement enhanced MUI progress system:
- File-size-based progress estimation (larger files = longer processing time)
- Better visual feedback with CircularProgress/LinearProgress components
- Periodic polling to check transcription completion status
- More realistic progress simulation (upload → processing → transcribing → summarizing → complete)
