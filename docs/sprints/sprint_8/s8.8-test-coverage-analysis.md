## Technical Approach

### Frontend Testing Stack
- **Framework:** Vitest (configured in `vitest.config.ts`)
- **React Testing:** @testing-library/react
- **Mocking:** vi.mock for API services, external dependencies
- **Coverage Tool:** c8 (built into Vitest)
- **Target:** ~80% coverage on critical paths (auth, payment, meetings)

### Backend Testing Stack
- **Framework:** xUnit (configured in `MeetingSummarizer.Api.Tests`)
- **Mocking:** Moq for services, NSubstitute for interfaces
- **Test Database:** In-memory SQLite or test SQL Server instance
- **Coverage Tool:** Coverlet + ReportGenerator
- **Target:** ~80% coverage on critical paths (auth, payment, meetings)

### Coverage Calculation Philosophy
- **Critical Paths (P0/P1):** 80%+ required (auth, payment, data loss prevention)
- **Standard Paths (P2):** 60%+ acceptable (UI, validation, error handling)
- **Low Priority (P3):** 40%+ acceptable (edge cases, admin tools)
- **Overall Target:** ~80% weighted by business criticality

### CI/CD Pipeline Enforcement
- **Pull Request Policy:** All tests must pass before merge
- **Coverage Threshold:** Critical path coverage >= 80%
- **Status Checks:** Both frontend and backend test jobs must succeed
- **Branch Protection:** Enforced on `main` branch, no bypass allowed
- **Coverage Reporting:** Automated reports posted to PR comments

## Risk Mitigation

### Risk: Test Writing Takes Longer Than Estimated
- **Mitigation:** Prioritize P0/P1 gaps first, defer P2/P3 if time constrained
- **Fallback:** 80% target is aspirational, 70% on critical paths acceptable minimum

### Risk: Flaky Tests in CI/CD Pipeline
- **Mitigation:** Use proper mocking for external services (Stripe, Azure, OpenAI)
- **Mitigation:** Configure test timeouts appropriately for CI environment
- **Mitigation:** Retry flaky tests 2x before marking as failed

### Risk: Coverage Threshold Blocks Urgent Hotfixes
- **Mitigation:** Document exception process in `/docs/testing/ci-cd-policies.md`
- **Mitigation:** Repository admin can override branch protection for emergencies
- **Mitigation:** Require coverage remediation in follow-up PR within 48 hours

### Risk: Existing Code Hard to Test (Tight Coupling)
- **Mitigation:** Add seams for dependency injection where needed
- **Mitigation:** Refactor minimally to enable testing (don't rewrite)
- **Mitigation:** Document technical debt for future refactoring
